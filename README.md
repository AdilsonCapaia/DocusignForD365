# DocusignForD365

Author: Adilson Capaia  
Blog: The Rational Developer  
Year: 2026

Full custom DocuSign integration for Power Platform and D365.

## Overview

This project is a Dynamics 365 plugin that integrates with DocuSign to send documents for electronic signature directly from D365 records.

## Custom API: SendDocuSignSignatureCustomApi

This Custom API is the main entry point for triggering a DocuSign signature process from Dynamics 365.

### Input Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `EntityLogicalName` | String | Yes | The logical name of the Dataverse entity from which the signature is triggered (e.g., `trd_trdcontract`). |
| `RecordId` | String | Yes | The GUID of the record that holds the documents and contacts to be sent for signature. |
| `EnvelopeTemplateId` | String | Yes | The DocuSign template ID to use when creating the envelope. This template defines the signing flow and tab positions. |
| `EmailSubject` | String | No | The subject line of the email sent to recipients. Truncated to 100 characters if longer. Defaults to empty. |
| `EmailBody` | String | No | The body text of the email notification sent to each recipient. Defaults to empty. |
| `IsInPerson` | Boolean | No | When `true`, recipients are created as In-Person Signers (the current user acts as the host). When `false`, recipients are standard remote Signers. Defaults to `false`. |

### Output Parameters

| Parameter | Type | Description |
|-----------|------|-------------|
| `EnvelopeId` | String | The unique ID of the Envelope generated by docusign after creation |
| `EnvelopeStatus` | String | The current status of the new created envelope( created/draft, sent, etc ) |
| `EnvelopeUri` | String | The url of the newly created envelope. It is usefull if you want to open the current envelope just after the creation to perform manually adjustement |

### How It Works

1. **Read parameters**: The plugin reads input parameters from the Custom API request like ( from butoon with a javascript trigger )
2. **Build recipients/Signatory**: Retrieve contacts linked to the current record on this case TRD Contract via the `trd_TRDContract_Contact_Contact` many-to-many relationship. Only contacts where `trd_iseligibleasrecipient = true` are included. It can be adpated to you needs. This ilustrate that any complex criteria can be achieved if you modify your BuildRecipients method 
3. **Retrieve documents**: Retrive documents from `trd_document` where `trd_docusignrequiredcode = true` and `trd_regardingid` matches the record. File colomn store content as byte  and we converted to base64 before send to Docusign API
4. **Create envelope**: Sends a composite template envelope to DocuSign with the template, recipients, and documents.
5. **Track in D365**: Creates a `trd_docusignenvelope` record to track the envelope status, and `trd_docusignenvelopedocuments` records for each attached document. This is importante when you whant to track each progress of you demanded signature. Also importante for the Inbound part we will build later( when docusign will notify D365 that signature was completed, reject, or in pause via Azure function Webhook)

### Environment Variables Required

| Schema Name | Description |
|-------------|-------------|
| `trd_DocuSignAuthBaseUrl` | DocuSign OAuth base URL (e.g., `account-d.docusign.com` for demo) |
| `trd_DocuSignBaseUrl` | DocuSign REST API base URL (e.g., `https://demo.docusign.net`) |
| `trd_DocuSignAccountId` | Your DocuSign account ID |
| `trd_DocuSignIntegrationKey` | The integration key (client ID) from your DocuSign app |
| `trd_DocuSignPrivateKey` | The RSA private key (PEM format) for JWT authentication |
| `docusign_ShouldAddPhoneNumber` | Set to `yes` to enable SMS authentication for recipients with a mobile phone |

### Prerequisites

- A DocuSign developer or production account
- A DocuSign app configured with  (RSA keypair, that you can create from docusign it self)
- A `docusign_user` entity in D365 mapping CRM system users to DocuSign user IDs
- Environment variables configured in Dataverse with the values above
- Contacts linked to the TRD Contract via the M:N relationship with `trd_iseligibleasrecipient = true`
- Documents attached to the record in `trd_document` with `trd_docusignrequiredcode = true`
